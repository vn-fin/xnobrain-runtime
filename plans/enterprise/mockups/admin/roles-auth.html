Roles & authentication

Pluggable auth. Roles defined in versioned config, assignments in the database.

Self-hosted note: the same auth service is swappable — local accounts, OIDC/SAML SSO, LDAP, or a custom org auth service. A firm running air-gapped uses the local backend with zero external egress.
Roles & auth · defined in auth.yaml (versioned, hot-reload)
# auth.yaml — versioned in Git, hot-reloaded by the control plane
auth:
  backends:
    - kind: oidc          # Okta
      issuer: "https://nimbus.okta.com"
      scim: true
    - kind: local         # argon2id · break-glass admin · air-gapped
      enabled: true

roles:
  org_admin:                  # full management + read-all
    - members.*
    - policies.write
    - devices.manage
    - voice.manage
    - usage.read_org
    - audit.read
  org_manager:                # read-all oversight, no member management
    - usage.read_org
    - devices.read
    - audit.read
  member:                     # self-scope only
    - usage.read_self
  auditor:                    # audit read only
    - audit.read

group_mappings:               # IdP group → role
  "nimbus-it-admins": org_admin
  "nimbus-eng-leads": org_manager
  "nimbus-eng":        member

provisioning:
  scim: true
  self_signup: false       # org-created accounts only

This config-file-first design is exactly what lets the same control plane run self-hosted (including air-gapped with the local backend and zero external egress) or on our managed cloud — an ops team defines roles/permissions in versioned YAML without touching a database console.
